손으로 그리는 대신, 코드로 짠 디자인 기획안

디자인 프로그램을 직접 다루지는 못하지만, 디자인팀에 넘길 기획안은 정확해야 했습니다. PowerPoint를 코드로 조작해 캐릭터 조합·배너·POP 레이아웃 시안을 직접 만들고, 피드백을 받을 때마다 코드를 고쳐 다시 뽑아냈습니다.

배경

키캡키링 캐릭터 조합, 부스 배너, 아크릴 POP 스탠드 — 디자인팀에 제작을 의뢰하려면 그 전에 콘셉트와 레이아웃을 구체적인 시안으로 만들어 전달해야 했습니다. 최종 디자인은 디자인팀 몫이지만, "무엇을 어떻게 만들어 달라"는 기획안은 제가 준비해야 했습니다.

문제

파워포인트를 손으로 직접 만지면 시안 하나 만드는 데도 시간이 걸리고, 팀장 피드백을 받을 때마다 같은 작업을 처음부터 반복해야 했습니다. 색을 하나 바꾸려 해도 슬라이드 곳곳의 도형을 일일이 찾아 고쳐야 하는 구조였습니다.

처음 생각과, 바뀐 판단

처음엔 "다음 시안도 손으로 만들면 되겠지"라고 생각했습니다. 그런데 캐릭터 조합만 4가지, 색 팔레트 후보도 여러 개인 상황에서 매번 손으로 배치하다 보니 시간이 배로 들었습니다. 그래서 접근을 바꿨습니다 — 슬라이드를 손으로 만들지 않고, 슬라이드를 만드는 코드를 짜는 쪽을 택했습니다. 색과 텍스트를 변수로 빼두면, 팀장 피드백이 와도 값 몇 개만 바꿔 다시 실행하면 됐습니다.

실행
  • PowerShell + PowerPoint COM 자동화로 슬라이드를 코드로 생성. 색상 팔레트를 변수 테이블로 정의하고, 텍스트박스·도형·선을 함수로 만들어 재사용
  • 캐릭터 시트 이미지를 4분면으로 자동 크롭해 각 캐릭터를 슬라이드에 개별 배치하는 로직 작성 — 이미지를 직접 자르는 대신 좌표 계산으로 처리
  • 팀장 피드백을 반영하는 과정을 3단계로 나눠 반복: 전체 색감·구성을 다시 짜는 리빌드 → 구성 요소를 확정하는 마무리 → 슬라이드별 문구만 미세 조정. 마지막 단계는 PowerPoint COM으로 특정 도형의 텍스트만 찾아 바꾸고 검토용 PNG로 즉시 내보냄
  • Python(python-pptx)으로 POP 스탠드 레이아웃 기획안을 별도 생성 — 슬라이드 크기·색상·폰트를 코드로 지정해 디자인팀 전달용 문서 완성
  • HTML/CSS/SVG로 인쇄 시안 목업까지 코드로 제작 — QR코드와 도시 스카이라인을 직접 벡터로 그려 시각 자료에 포함
결과

수정 요청이 올 때마다 처음부터 다시 만들지 않고, 코드 몇 줄을 고쳐 즉시 새 버전을 뽑아냈습니다. 만든 기획안·의뢰서는 디자인팀에 전달했고, 실제 인쇄·제작은 디자인팀이 완성했습니다. 제 몫은 그 전 단계 — 의도를 구체적인 시안으로 옮겨 전달하는 일이었습니다.

증거 자료 · 실제 스크립트 코드 (프로젝트 경로·파일명은 비공개)
function Crop-Quadrants { param([string]$Source, [string]$Prefix) $image = [System.Drawing.Image]::FromFile($Source) $halfW = [int]($image.Width / 2) $halfH = [int]($image.Height / 2) $items = @( @{ Name = 'cat'; X = 0; Y = 0 }, @{ Name = 'dog'; X = $halfW; Y = 0 }, @{ Name = 'penguin'; X = 0; Y = $halfH }, @{ Name = 'hedgehog'; X = $halfW; Y = $halfH } ) # 캐릭터 시트 한 장을 4분면으로 잘라 개별 배치 }

스크립트 9개 중 하나. 색상·좌표를 변수로 분리해, 팀장 피드백이 오면 값만 바꿔 재실행하는 구조로 작성했습니다.
