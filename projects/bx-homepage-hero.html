홈페이지 히어로 모션 시안

회사 홈페이지 첫 화면을 스크롤 모션으로 바꾸는 방안을, 확정 전에 눈으로 볼 수 있는 시안으로 만들었습니다. 방향이 다른 A안·B안을 먼저 만들고, 두 안을 합친 C안까지 3종입니다.

주어진 과제
지금 홈페이지의 첫 화면은 이미지 슬라이드입니다. 모션 방향을 확정하기 전에, 글로 된 설명이 아니라 직접 움직여 볼 수 있는 시안이 필요했습니다.
내 역할
기획안 작성(콘셉트·장면 구성·문구 출처 정리·팀장에게 확인받을 항목), 벤치마크 선정, 시안 점검과 수정. 작동하는 HTML 시안은 AI 코딩 에이전트와 함께 만들었고, 화면은 직접 열어 확인했습니다.
결과
기획안 2판, 작동하는 프로토타입 3종(A·B·C안), 접근성·모션 점검표, 시안 비교 화면(A/B/C·PC/모바일)을 팀장 검토용으로 만들었습니다. 적용 여부는 아직 정해지지 않았고, 사용자 반응 수치는 없습니다.
이 경험으로 할 수 있는 일
새 화면 방향을 확정 전에 작동하는 시안으로 보여주고, 검토에서 나온 수정 요청을 목록으로 관리해 다음 시안에서 같은 문제가 다시 나오지 않았는지 확인할 수 있습니다.

기획 흐름

  1. 홈페이지 읽기현재 홈페이지 메인의 문구·구성·서비스·사례를 읽고 기획안의 문구를 모두 홈페이지 원문으로 맞췄습니다. 처음에는 브로셔 기준으로 썼다가 홈페이지 기준으로 정렬했고(v1.1), 새로 지어낸 문구는 넣지 않았습니다.
  2. 벤치마크 나누기참고한 사이트에서 가져온 것(연출 방식), 새로 만든 것, 가져오지 않은 것(코드·이미지·문구)을 표로 나눠 적었습니다. 1차는 포스코 이스틸포유, 2차는 수상작 목록에서 찾은 루아소프트를 참고했습니다.
  3. 장면 구성히어로 → 서비스 7개 → CRM 예시 → 세일즈 교육 4단계 → 수행사례 → 인사이트 → 전국 거점 → 고객 로고 → 문의, 9개 구간입니다. A안(1차)의 콘셉트는 "줄무늬 BX가 7개 서비스로 갈라진다"이고, B안(2차)은 흰 바탕에서 화면이 고정된 채 장면이 바뀌는 방식입니다. C안은 B안의 구성에 A안의 스크롤 감각을 합친 안입니다.
  4. 확인받을 것 분리팀장에게 결정받을 항목(적용 방식, 문구 순서, 고객 로고 사용 범위, 홈페이지 데이터 연동, BX 로고 벡터 파일)과 시안에서 동작하지 않는 부분(문의 창, 고정된 사례·인사이트 내용)을 기획안에 따로 적었습니다.
  5. 점검과 수정1차 프로토타입을 웹 접근성 기준과 디자인 점검 도구로 훑어 반드시 고칠 것 5건, 고치는 편이 좋은 것 14건, 디자인 판단이 필요한 것 8건을 표로 정리했습니다. 27건 중 26건을 10월 15일에 반영했고, 어두운 테마 하나로 가는 방향 1건은 사용자 결정이 필요해 남겼습니다.
  6. 수정 요청 반영A안을 검토하며 나온 수정 요청 10가지를 목록으로 만들고, B안에서 하나씩 처리했는지 확인했습니다.
  7. 합본 C안B안을 기본으로 두고 PC·모바일을 한 페이지로 합쳤습니다. 스크롤 고정 구간을 9.2화면에서 7.6화면으로 줄이고 반응 속도를 A안 수준으로 맞췄습니다. 첫 화면은 검정에서 시작해 줄무늬가 가늘어지며 흰 바탕으로 바뀝니다. 하단은 홈페이지와 같은 구조(문의 카드와 레터 구독 카드를 나란히)로 맞췄습니다.

같은 기준으로 이어서 만든 두 작업

C안의 색·버튼·카드 기준을 그대로 써서 산업별 교육 페이지와 CRM 체험 페이지로 넓혔습니다. 둘 다 운영 사이트에는 반영되지 않았습니다.

작업만든 것내가 정한 것한계
산업별 세일즈 교육 페이지제약·IT·반도체를 서비스 앞 "산업" 메뉴로 소개하는 페이지 4개(전체보기 포함)와 기획안. 산업 현재·전망 → 관점 → 기여 영역 → 관련 경험 → 대표 교육안 → 현업 적용·문의 순서세 산업 모두 직접 수행사례와 확정 강사가 없어 실적을 만들지 않았습니다. 산업 배경은 공개 자료(IQVIA, McKinsey, SEMI)로 인용하고 자사 해석은 따로 표시했습니다. 모션 그래픽은 "밋밋하고 세 산업이 같아 보인다"는 지적을 받아 점등 방식에서 의사결정자의 질문(제약=MR 방문, IT=사용·IT·구매 부서, 반도체=평가 관문)에서 출발하는 방식으로 여러 번 다시 만들었습니다. 산업 장면 이미지 3장은 AI로 생성했고 화면에 그렇게 표기했습니다.질문 문구와 교육 구성은 공개 자료와 자사 해석에 기반한 초안이며 해당 산업 현업의 검증을 받지 않았습니다.
CRM 체험 페이지공개 홈페이지의 CRM 예시 소개·체험 화면에 C안의 색·버튼·카드와 최소한의 모션을 적용해 저장소에 14개 커밋으로 반영상세 슬라이드 패널과 대시보드 2단 구성을 만들어 본 뒤 기존 구조로 되돌렸습니다. 업무 화면에는 익숙한 아코디언이 낫다고 판단했습니다. 이전 값이 없는 가상 데이터에는 추세 화살표를 붙이지 않았고, 단계 이동은 검증된 업무 양식을 거치도록 보드 드래그 이동은 뺐습니다. 새 라이브러리는 쓰지 않았습니다.운영 배포는 배포 도구의 접근 권한 문제로 대기 중입니다.

두 작업도 화면과 모션 구현은 AI 코딩 도구(Claude Code, Codex)가 했습니다. 벤치마크 교체, 스크롤 대신 자동 재생, 속도·정렬 결정, 시도한 화면을 보고 채택·폐기를 정하는 일, 운영 사이트와의 용어·문구 대조 요청은 제가 했습니다.

확인한 것과 못한 것

확인함
CRM 체험 페이지(10월 21일 기준): 테스트 459건 통과, 타입 검사 오류 0건, 1440px·390px 화면, 모션 줄이기 상태. 산업별 페이지: 375·768·1024·1440px에서 다섯 페이지 20개 조합 가로 넘침 없음, 탭 키보드 전환·문의 창·모바일 메뉴. B안(10월 16일 기준): 데스크톱 1280px 전 구간, 900px에서 1600px로 크기 변경, 모바일 375px 전 구간(가로 넘침 없음), 인트로와 문구 순환, 스크롤 동작, 콘솔 오류 없음
확인하지 못함
C안과 10월 19일 수정분을 화면으로 다시 점검한 기록(수정 내역은 작업 기록 기준), 실제 휴대기기와 저사양 PC에서의 부드러움, 산업 현업의 검증(성능 수치는 측정하지 않았습니다), 크롬 외 브라우저, 마우스 휠로 느끼는 스크롤 속도, 동작 줄이기 설정 화면(코드만 작성)
아직 없는 것
실제 홈페이지 적용, 사용자 반응이나 방문 지표. 이 시안은 방향을 정하기 위한 것이며 성과를 낸 결과물이 아닙니다.

시안 속 그래픽의 숫자는 이해를 돕기 위한 예시이며 실적이 아닙니다. 회사 홈페이지 화면과 고객사 로고는 이 페이지에 넣지 않았습니다.
