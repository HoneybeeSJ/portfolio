주어진 과제
지금 홈페이지의 첫 화면은 이미지 슬라이드입니다. 방향을 확정하기 전에 글 설명이 아니라 직접 움직여 볼 수 있는 시안이 필요했고, 전문 강사를 섭외해 신규 산업 교육 시장을 여는 구상을 홈페이지에서 소개할 페이지도 필요했습니다.
내 역할
방향 합의와 선택(벤치마크 교체, 스크롤 대신 자동 재생, 속도·정렬), 실적과 강사를 만들지 않는 사실의 경계 설정, 시도한 화면을 보고 채택·폐기 결정, 운영 사이트와의 용어·문구 대조 요청. 화면과 모션 구현은 AI 코딩 도구(Claude Code, Codex)가 했습니다.
결과
홈 시안 3종과 기획안 2판, 산업별 페이지 4개와 기획안, CRM 체험 페이지(저장소 반영)를 만들었습니다. 모두 운영 사이트에는 반영되지 않았고, 사용자 반응 수치는 없습니다.
이 경험으로 할 수 있는 일
새 화면 방향을 확정 전에 작동하는 시안으로 보여주고, 검토에서 나온 수정 요청을 목록으로 관리할 수 있습니다. 실적이 없는 영역은 지어내지 않고 범위를 표기해 소개 페이지를 쓸 수 있습니다.

홈 모션 개편 시안

이미지 슬라이드 홈을, 스크롤 모션 중심 홈으로 바꾸는 제안입니다. 현재 홈페이지의 문구와 서비스 7개는 그대로 쓰고, 고객사 의사결정자에게 "한 팀이 전부 해결한다"는 인상을 주는 홈을 제안했습니다.

  1. 벤치마크를 바꿔 두 시안 만들기1차는 어두운 바탕의 스크롤 연출(포스코 이스틸포유 참고), 2차는 다른 사례(루아소프트)를 기준으로 밝은 바탕으로 다시 만들고, 둘의 장점을 합쳐 C안으로 정리했습니다. 벤치마크에서 가져온 것(연출 방식), 새로 만든 것, 가져오지 않은 것(코드·이미지·문구)은 표로 나눠 적었습니다.
  2. 뼈대는 그대로 두기홈의 일곱 섹션 순서와 CMS, 문의 기능은 바꾸지 않고 배치와 모션만 제안했습니다. 문구는 현재 홈페이지 원문 기준이고, 새로 쓴 문구는 따로 표시해 승인을 받도록 했습니다.
  3. 구성히어로에서 빛줄기가 BX로 모이고 세 문구가 순환합니다. 서비스 7개는 스크롤하면 서비스별 모션 그래픽이 차례로 바뀌는 고정 화면이고, 세일즈 교육 4단계(진단, 문제유형 매칭, 과정 설계, 현업 적용 상담)는 스크롤에 맞춰 켜집니다. 그래픽 속 수치는 예시이며 화면에도 그렇게 표기했습니다.
  4. 보고서로 분리하기일곱 섹션 중 세 개는 새로 제작, 네 개는 겉모습과 배치 변경이라는 변경 수준을 나눴고, 팀장 승인이 필요한 네 가지(삭제 항목 3건, 새 소개 문구, 외부 라이브러리 3종, 밝은 바탕과 어두운 바탕 선택)를 따로 적었습니다.
  5. 점검과 수정 요청 반영접근성·디자인 점검 27건 중 26건을 반영했고(1건은 사용자 결정 필요), A안 검토에서 나온 수정 요청 10가지를 목록으로 만들어 B안에서 하나씩 처리했는지 확인했습니다.

산업별 세일즈 교육 페이지

제약, IT, 반도체 세 산업을 서비스 앞 "산업" 메뉴로 소개하는 페이지 4개(전체보기 포함)와 기획안입니다. 영업본부장과 사업부장이 먼저 읽는다고 보고, 산업의 현재와 전망, BX의 관점, 기여 영역, 관련 경험, 대표 교육안, 현업 적용 순으로 구성했습니다.

  1. 만들어내지 않기세 산업 모두 직접 수행사례와 확정 강사가 없어, 공통 경험은 범위를 표기해 쓰고 산업 실적과 강사는 지어내지 않았습니다. 화면에도 그렇게 표기했습니다.
  2. 출처와 해석 분리산업 배경은 공개 자료(IQVIA, McKinsey, SEMI)를 인용하고 BX의 해석은 따로 표시했습니다. 산업 장면 이미지 3장은 AI로 생성했고 화면에 그렇게 밝혔습니다.
  3. 모션 그래픽을 여러 번 다시 만들기처음 버전은 "밋밋하고 세 산업이 같아 보인다"는 지적을 받았습니다. 스크롤 연동, 워크시트형 등을 시도한 끝에 의사결정자가 속으로 묻는 질문에서 출발하는 방식으로 정했습니다. 제약은 정보 접점 사이에 MR 방문이 놓이는 흐름, IT는 사용·IT·구매 부서가 각자 묻고 하나의 제안이 답하는 구조, 반도체는 평가 관문을 하나씩 통과하며 대응계획으로 정리되는 구조입니다.
  4. 운영 사이트와 맞추기운영 코드의 메뉴, 문의 문구, 진행 단계, 과정 목록과 대조해 용어(세일즈 교육), 단계 이름, 문제별 솔루션 링크, 브랜드 표기를 맞췄습니다. 반도체의 질문 문구는 예시로 표기했고 현업 검증은 받지 못했습니다.

CRM 체험 페이지

공개 홈페이지의 CRM 예시 소개·체험 화면(창호업 상담 CRM 기반)에 C안의 색, 알약 버튼, 카드 모양을 적용하고 최소한의 모션을 더해 저장소에 14개 커밋으로 반영했습니다. 이 CRM은 제가 먼저 만든 화면을 바탕으로 팀장님이 일부 수정하거나 참고해 새로 만든 부분이 섞여 있어, 아래는 제가 C안 디자인과 모션을 적용한 범위입니다.

  1. 되돌린 시도상세 슬라이드 패널과 대시보드 2단 구성을 만들어 본 뒤 기존 구조로 되돌렸습니다. 업무 화면에서는 익숙한 아코디언이 낫다고 판단했습니다.
  2. 넣지 않은 것이전 값이 없는 가상 데이터에는 추세 화살표를 붙이지 않았고, 단계 이동은 검증된 업무 양식을 거치도록 보드의 드래그 이동은 뺐습니다. 새 라이브러리 없이 CSS와 작은 스크립트만 쓰고, 모든 모션은 모션 줄이기 설정에서 꺼집니다.
  3. 최종 검수에서 찾은 문제스크롤을 크게 내리면 건너뛴 패널이 보이지 않는 오류를 찾아 고쳤습니다. 운영 배포는 배포 도구의 접근 권한 문제로 대기 중입니다.

확인한 것과 못한 것

확인함
산업별 페이지는 375·768·1024·1440px에서 다섯 페이지 20개 조합의 가로 넘침 없음, 탭 키보드 전환, 문의 창, 모바일 메뉴, 모션 줄이기 상태를 확인했습니다. 터치 영역 44px, 글자 12px 이상, 모션 안 글자 대비 4.5:1 이상도 측정했습니다. CRM 체험 페이지는 테스트 459건 통과, 타입 검사 오류 0건, 1440px와 390px 화면을 확인했습니다.
확인하지 못함
실제 휴대기기, Safari, Firefox(데스크톱 크롬 기준 검증), 산업별 문구와 교육 구성에 대한 해당 산업 현업의 검증
아직 없는 것
운영 사이트 반영(홈 시안은 승인 대기, 산업별 페이지는 내부 검토본, CRM은 배포 대기), 사용자 반응이나 방문 지표. 이 작업은 방향을 정하기 위한 제안이며 성과를 낸 결과물이 아닙니다.

시안 속 그래픽의 숫자와 질문 문구는 이해를 돕기 위한 예시이며 실적이 아닙니다. 회사 홈페이지 화면과 고객사 로고는 이 페이지에 넣지 않았습니다.

AI와 사람이 나눠 한 일

구현 속도는 AI가 냈고, 무엇을 만들지와 무엇을 만들지 않을지는 제가 정했습니다.

AI가 한 일제가 한 일
화면과 모션 구현(Claude Code, Codex)과 반복 수정. 화면 크기별 검증 스크립트, 대비·터치 영역·글자 크기 측정. 기획안과 검증 문서 초안, 산업 장면 이미지 3장 생성방향 합의와 선택, 사실의 경계 설정(실적·강사 미창작, 출처와 해석 분리), 시도한 화면을 직접 보고 채택과 폐기 결정, 운영 사이트와의 정합성 대조 요청과 어긋난 항목 정리
